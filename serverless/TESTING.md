# 動作テストの仕様（サーバーレス版）

どの変更のあとに、どこで、何を確かめるかをまとめる。

| 段階 | どこで | いつ | 所要時間 |
|---|---|---|---|
| A. 自動テスト | 手元（`npm run test:serverless`） | コードを変えたら毎回。コミットの前 | 1秒 |
| B. テスト環境での全項目 | mogiri-test（テスト用アプリとテスト用サーバー） | コードを変えて mogiri-test にデプロイしたあと。本番にデプロイする前 | 30分（コールドスタートを含めると45分） |
| C. 本番での確認 | 本番の mogiri | 本番にデプロイしたあと、Secret や設定を変えたあと | 5分 |
| D. イベント前の確認 | 本番の mogiri | イベントの前日か当日の朝 | 10分 |

- B は **本番の受付には一切触れない**。C と D は、記録が残らない操作と、テスト用注文番号だけを使う
- 本番で、実際の参加者の注文番号を使って試さない（受付の記録と「何枚目か」の数が変わる）
- 結果は、それぞれの項目の「期待する結果」と同じかで判断する。違ったら本番へ進まない

## A. 自動テスト

```bash
npm run test:serverless
```

外部には接続しない（Discord と Pretix は偽物、D1 は `node:sqlite` と本物の `schema.sql`）。次を確かめている。

| 分類 | 確かめていること | ファイル |
|---|---|---|
| 署名 | 正しい署名だけ通る。改ざん・別の鍵・古いタイムスタンプ・ヘッダーなしは 401 | `test/discord.test.js`、`test/worker.test.js` |
| 受付 | ロールを付け、注文番号を含まない記録を投稿する。何枚目かを数える。全角・小文字・`#` 付きを同じ注文とみなす | `test/worker.test.js` |
| 受付の失敗 | 無効な注文、入場券でない注文、ロールがない、Bot の権限不足、Secret がない、別のサーバーのカンファレンス | `test/worker.test.js` |
| 3秒の制限 | 時間のかかる処理の前に deferred 応答を返す | `test/worker.test.js` |
| 投稿の失敗 | 受付チャンネルへの投稿が失敗・タイムアウトしても、本人への結果は変わらない | `test/worker.test.js` |
| 試行回数の上限 | 10分に5回で止める。ユーザーごとに数える。上限で止めた試行とロール持ちは数えない | `test/worker.test.js` |
| 管理コマンド | `ADMIN_USER_IDS` 以外は拒否。追加・削除・一覧。Pretix の URL と Secret 名の制限。別サーバーの名前を奪えない | `test/worker.test.js` |
| Pretix | 支払い済みで入場券を含む注文だけ有効。ページ送り、タイムアウト、トークンを別のホストに送らない | `test/pretix.test.js`、`../test/pretix.test.js` |
| Discord REST | メンションを無効にして投稿する。429 で1回だけやり直す | `test/discord.test.js` |
| 移行スクリプト | config.json からキーを出さずに SQL を作る。過去の記録の取り込みを2回しても重複しない | `test/scripts.test.js` |

自動テストでは確かめられないもの（B で確かめる）: 本物の Discord の表示、本物の Pretix の応答、Cloudflare の Secret と D1 の設定、コールドスタート。

## B. テスト環境での全項目（mogiri-test）

準備（初回だけ）は [README.md](README.md) の「テスト用アプリでの動作確認の手順」の 1〜3。

用意するもの:

- テスト用サーバーと、そこにいる2つのアカウント（管理者の自分と、`ADMIN_USER_IDS` にない別のアカウント）
- テスト用カンファレンス `rsgt2027`（参加者ロール `RSGT2027参加者`）と、そのイベントの次の注文番号
  - 有効な注文（入場券を含む、支払い済み）
  - 入場券を含まない注文（あれば）
- `npx wrangler tail` を別のターミナルで開いておく

各項目を始める前に、自分のアカウントから参加者ロールを外しておく（B-1x の受付項目）。

### 基本

| ID | 操作 | 期待する結果 |
|---|---|---|
| B-01 | `/mogiri` | 全員に見える形で案内が返る |
| B-02 | Bot との DM で `/mogiri` 以外のコマンド | 「サーバー内のチャンネルで実行してください。」（コマンドが DM に出ない場合は省略） |
| B-03 | 署名なしで Worker の URL に POST（`curl -X POST <URL> -d '{}'`） | 401 |

### 管理コマンド

| ID | 操作 | 期待する結果 |
|---|---|---|
| B-04 | `/mogiri-admin add name:rsgt2027 role:RSGT2027参加者 organizer:<organizer> event:<slug> key_secret:PRETIX_KEY_SCRUMGATHERING test_order:<有効な注文番号>` | 本人にだけ「追加しました」（すでにあれば「更新しました」）。数秒で `/rsgt2027` が使える（出ないときは Ctrl+R）。`test_order` は全角・小文字・`#` 付きでも受け付ける |
| B-05 | `/mogiri-admin list` | 本人にだけ一覧。Pretix のイベントの URL はひと続きのリンクで、プレビューが出ない。Secret 名はコードの表示（`_` が消えない）。トークンの値は出ない |
| B-06 | `/mogiri-check` | 記録件数、ロールが見つかったか、テスト用注文番号が有効か、チケット枚数が出る（Secret の行は、未設定のときだけ出る）。注文番号はチャンネルに出ない |
| B-07 | 別のアカウントで `/mogiri-admin list` | 拒否される（コマンドが見えないときは、連携サービスで一時的に許可して試す） |
| B-08 | `/mogiri-admin add` で `base_url:https://example.com` | 「base_url は次のいずれかにしてください: `https://pretix.eu`」で拒否される。URL にプレビューが付かない |
| B-09 | `/mogiri-admin add` で `key_secret:DISCORD_BOT_TOKEN` | 「key_secret は `PRETIX_KEY_` で始まる…」で拒否される。`PRETIX_KEY_` が斜体にならず、`_` が見える |
| B-09a | `/mogiri-admin analytics` | 本人にだけ、カンファレンスごとに「受付 N枚（注文 M件）・今日 K枚」。Pretix は呼ばれない |
| B-09b | `/mogiri-admin analytics name:rsgt2027` | 上に加えて「販売 S枚（支払い済みの入場券）・受付率 X%」。販売枚数は Pretix の管理画面の支払い済みの入場券の数と同じ |
| B-09c | `/mogiri-admin whois user:` で、B-10 で受付したアカウントを選ぶ | 本人にだけ、受付の記録（注文番号と何枚目か）、参加者ロールの有無、直近の試行回数が出る |
| B-09d | `/mogiri-admin order number:<B-10 で使った注文番号>` | 本人にだけ、受付の回数と、何枚目をだれがいつ受付したか、Pretix での入場券の枚数が出る。受付が枚数より多ければ「多く受付されている」と出る |

### 受付

| ID | 操作 | 期待する結果 |
|---|---|---|
| B-10 | `/rsgt2027 ordernumber:<有効な注文番号>` | 本人にだけ「認証が完了」。ロールが付く。受付チャンネルに `@自分 のチェックインを確認し… [rsgt2027] (N/M枚目)`（注文番号は出ない） |
| B-11 | ロールを持ったまま、もう一度 B-10 | 「すでに…ロールをお持ちでした」。枚数は増えない |
| B-12 | ロールを外し、注文番号を全角・小文字・先頭に `#` を付けて入力（例: `ABC12` なら `＃ａｂｃ１２`） | B-10 と同じ注文として受け付けられ、枚数が1つ増える |
| B-13 | 別のアカウントで同じ注文番号 | `(N+1/M枚目)` になる。枚数を超えても受付は通る（表示だけ） |
| B-14 | 存在しない注文番号（例: `ZZZZZ`） | 本人には失敗の案内。受付チャンネルには注文番号なしの失敗の記録 |
| B-15 | 入場券を含まない注文 | 「入場券ではない」 |
| B-16 | 存在しない注文番号を続けて6回 | 6回目は「確認の回数が上限…に達しました」。6回目はチャンネルに投稿されない。10分たつと再び試せる |

### 失敗したときの動き

| ID | 操作 | 期待する結果 | 終わったら |
|---|---|---|---|
| B-17 | サーバー設定 > ロールで、Bot のロールを参加者ロールより下に移してから受付 | 「ロールを付けられませんでした」。記録件数（`/mogiri-check`）は増えない | ロールの順番を戻す |
| B-18（任意） | 受付チャンネルで Bot の「メッセージを送信」を拒否してから受付 | 本人には「認証が完了」、ロールも付く。tail に `failed to post the check-in record` | 権限を戻す |
| B-19 | `/mogiri-admin remove name:rsgt2027` | `/rsgt2027` が消える | B-04 で入れ直す |

### 設定とデプロイ

| ID | 操作 | 期待する結果 |
|---|---|---|
| B-20 | `npm run deploy` のあと `npx wrangler secret list` | `DISCORD_PUBLIC_KEY`、`ADMIN_USER_IDS`、`DISCORD_BOT_TOKEN`、`PRETIX_KEY_...` が残っている |
| B-21 | `serverless/.env` を一時的に別名にして `npm run deploy` | `CLOUDFLARE_ACCOUNT_ID が指定されていません` で止まり、何もデプロイされない |
| B-22 | `npx wrangler versions view <デプロイした版>` | D1 の ID が今までの mogiri-test のもの（新しい空の D1 が作られていない） |

### 時間がかかるもの

| ID | 操作 | 期待する結果 |
|---|---|---|
| B-23 | 15分以上だれも使っていない状態で `/mogiri` と B-10 | 「アプリケーションが応答しませんでした」にならない |
| B-24 | 全項目のあとで tail を見る | 意図して起こした失敗（B-17、B-18）以外にエラーがない |

B-18 は、Bot の権限や受付チャンネルの扱いを変えたときだけ行う（投稿の失敗は自動テストで確かめている）。

コードの変更が一部だけのときも、B-01、B-04〜B-06、B-10、B-14、B-20、B-24 は毎回行う。変えた部分に関係する項目を足す。

## C. 本番での確認（本番の mogiri）

本番にデプロイしたあと、または `secret put` などで設定を変えたあとに行う。受付の記録が増える操作はしない。

| ID | 操作 | 期待する結果 |
|---|---|---|
| C-01 | `npx wrangler secret list --env production` | 必要な Secret がそろっている |
| C-02 | 本番のサーバーで `/mogiri` | 案内が返る（署名の検証が通っている） |
| C-03 | `/mogiri-admin list` | 一覧が出る（`ADMIN_USER_IDS` が効いている） |
| C-04 | `/mogiri-check` | ロールが見つかり、テスト用注文番号が有効と出る |
| C-04a | `/mogiri-admin analytics`（コマンドの定義を変えたデプロイのあとは、先に `/mogiri-admin sync`） | 受付枚数が出る |
| C-05 | `npx wrangler tail --env production` を数分見る | エラーがない |

C-02 が「アプリケーションが応答しませんでした」になったら、すぐに直前の版に戻す（`npx wrangler rollback --env production`）。

## D. イベント前の確認

イベントの前日か当日の朝に、受付をするサーバーで行う。

| ID | 操作 | 期待する結果 |
|---|---|---|
| D-01 | C-01〜C-05 | すべて期待どおり |
| D-02 | `/mogiri-admin list` | そのイベントのカンファレンスがあり、Secret に `⚠️未設定` がない |
| D-03 | `/mogiri-check` と、サーバー設定 > ロール | テスト用注文番号が有効と出る。ロールの一覧で、参加者ロールが Bot のロールより下にある（`/mogiri-check` はロールの順番までは見ない） |
| D-04 | 参加者の権限で `/<カンファレンス名>` がコマンドの一覧に出るかを、運営のだれかに見てもらう | 出る |
| D-05 | 切り戻し先の Azure の Web アプリを起動する（[README.md](README.md) の切り替え手順 7） | Bot がオンラインになる。Endpoint URL はまだ変えない |
